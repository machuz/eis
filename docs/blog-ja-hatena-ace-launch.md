# git だけで「コードベースの効きどころ」が見える —— OrbitLens Ace を公開しました

![Cover](https://raw.githubusercontent.com/machuz/eis/main/docs/images/blog/hatena/cover-ace-launch.png?v=1)

*コミット数は嘘をつく。でも、git に残ったコードは嘘をつかない。*

---

## 何ができるのか

誰が書いたコードが半年後も残っているか。どのモジュールが、たった一人の頭の中だけで生きているか。チームの誰が抜けたら構造が崩れるか。

これ、ぜんぶ git にもう書いてあります。読み方さえあれば。

コミット数・PR数・変更行数は「忙しさ」は映すけど「効きどころ」は映さない。タイポ修正もシステム全体の設計変更も「1 PR」。lockfile で数千行。でも、生き残ったコードは盛れない。

[EIS](https://github.com/machuz/eis) は、それを読む OSS の CLI です。`git log` と `git blame` だけでエンジニアリングを7軸で観測して、JSON に吐く。外部APIもAIトークンもいらない。`brew install` して `eis` を叩くだけ。

そして今日、その上に乗る SaaS、**[OrbitLens Ace](https://ace.orbitlens.io)** を公開しました。CLI が「観測する」なら、Ace は「観測を読んで、意味にする」ところです。

---

## EIS と Ace は役割が違う

ざっくり言うと、こう：

- **EIS（OSS CLI）= 観測する側。** git を読んでシグナルを返すだけ。推薦も予測もしない。式は全部[ホワイトペーパー](https://github.com/machuz/eis/blob/main/docs/whitepaper.md)に書いてあるので、中身は丸見え。
- **Ace（SaaS）= 観測を読む側。** そのシグナルを言葉にして、チームの構造を見せる。

なんで分けてるか。観測する道具が「意味」まで決め始めると、どこからが事実でどこからが意見か分からなくなるからです。EIS は事実に徹する。解釈は Ace の仕事。だから両方を信じられる。

---

## Ace で何が見えるか

**Structural Summary —— 数字を、文章に。**
「Survival が 23」とだけ言われても困りますよね。設計が弱いのか、ただレガシーを書き換え中なのか分からない。Ace はシグナル全体を読んで「いま何が立っていて、何が崩れかけているか」を文章で説明します。

**コンウェイの法則チェック —— 組織図 vs 実態。**
「このサービスはAチーム担当」。……本当に？ Ace は人のトポロジーとモジュールのトポロジーを並べて、組織図と実態がどこでズレているかを見せます。所有してるはずのチームが、実は書いていない。知識がいつのまにか別の人に移っていた。そういうやつです。

**崩壊リスク —— 時限爆弾を、爆発前に。**
誰も触らないから残っているだけのモジュール。オーナーが辞めて宙に浮いたモジュール。バスファクター1。リスクは最初から git 履歴の中にありました。Ace は、それが事故になる前に表に出します。

**組織年表（Chronicle）—— 個人的にいちばん気に入ってる部分。**
これは得点表じゃありません。エンジニアを順位づけない。代わりに「このコードベースが何をくぐってきたか」を記録します。乗り越えたマイグレーション、ある subsystem を作って去っていったアーキテクト、オーナーが変わって脆くなったモジュール。

なんでこうしたか。エンジニアリング指標って、だいたい「名前の横の数字」になって、順位づけと詰めに使われて死ぬんですよ。EIS は時間減衰 survival で「忙しさでは盛れない」ようにして、それに抗ってる。Ace も同じ姿勢を引き継ぎます。**測るのは「コードベースが何をくぐったか」で、「誰が偉いか」じゃない。** スコアは見たければ見れるけど、主役じゃなくて、近くで覗くときのレンズ扱い。

得点表は、人がゲームの仕方を覚える。年表は、愛着が湧く。狙ってるのは後者です。

## 使ってみる

扉は2つ。

**OSS の望遠鏡:**

```bash
brew install machuz/tap/eis
cd your-repo
eis analyze .
```

アカウントも連携もいりません。どのリポでも、向ければシグナルが返ります。

**SaaS の天文台:** [ace.orbitlens.io](https://ace.orbitlens.io)

GitHub を繋げば、Ace が観測を回しっぱなしにして、あなたの代わりに読んでくれます。

---

## CLI はずっと無料です

EIS（CLI）は完全無料・OSS。席数制限もトライアル期限も、「肝心なところだけ有料」のオープンコアもなし。式は全部公開、`brew install` 一発。誰でも自分のコードに向けて、こっちに何も聞かずに読めます。

アイデアに課金したいんじゃなくて、広がってほしいんです。「git からエンジニアリングは観測できる」「活動量より生存が大事」「静かに構造を支えてる仕事を、見えるようにしたい」。壁の向こうに置いたら、広がらない。

お金がかかるのは SaaS の Ace の方。観測を回し続けて読み返すのは、ちゃんとインフラなので。とはいえ壁じゃなく、手が届く値段にしました：

- **Free** $0 —— ソロ、または5人まで。公開リポ無制限、非公開いくつか、履歴6ヶ月。
- **Pro** $7/月 —— 個人。全期間の履歴、フルの Gravity Certificate。
- **Nova** $39/月（8席込）+ $18/席 —— 組織レベルの読み（コンウェイ、崩壊リスク、メンバー別の所有）が欲しい非公開チーム向け。

ちなみに、この手の分析 SaaS はだいたい「開発者1人あたり月 $15〜50」、しかも "contact sales" の向こう、が相場です。Ace は8席までフラットで、その下のエンジンは無料。少ないチームが高く払うより、多くのチームが自分のコードを見れる方がいい。

あと Gravity Certificate（持ち運べる証明書）は、どのプランでも作成も検証もずっと無料です。自分の仕事を証明するのに、お金は取りません。

## 最後に、正直なところ

ひとつ、ずっと引っかかってることがあります。エンジニアリングを「上から」測った瞬間 —— 経営目線とか、人を上から見渡す目線とか —— 現場の肌感覚って、平らに潰れがちなんですよね。数字が来ると、その人が実際にやったことの手触りが、その下に隠れてしまう。

その逆を作りたい。でも、できてるとは言い切れません。シグナルはシグナルで、判定じゃない。git に映らないもの —— メンタリング、コミットにならなかった設計の議論、障害のときに誰かが保ってた落ち着き —— は測らないし、「測れない」とはっきり言います。低いシグナルは「貢献が小さい」じゃなくて、たいてい「組織側のシグナル」です。

人を測るのは、善意でも危うい。現場の感覚を一度も貶さずに測る方法を、まだ見つけられたとは思ってません。だからこれは本気のお願いです。自分のを、チームのを見て「なんか違う」「平らにされた」「大事だったやつが抜けてる」と思ったら、教えてください。そのズレてる所が、次に直す場所だから。

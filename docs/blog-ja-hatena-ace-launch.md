# AIが1000行を1分で吐く時代に、本当に効くコードはどれか。OrbitLens Ace を公開しました

![Cover](https://raw.githubusercontent.com/machuz/eis/main/docs/images/blog/hatena/cover-ace-launch.png?v=1)

*AIは無限にコードを書ける。残せるかどうかは、別の話だ。*

---

どのリポジトリにも、記録が二つ眠っています。

ひとつはみんなが読む方。コミットログ、PR数、変更行数。要するに活動量、誰がよく動いたか。
もうひとつは、ほとんど誰も読まない方。半年後もそのコードが残っているか。blame が結局誰に当たるか。こっちが構造です。

マネジメントはたいてい前者を見て、後者に足をすくわれます。「あの人が抜けたら、あのサブシステム誰も分からない」。その崩壊は、ずっと後者の記録に書いてあった。読んでいなかっただけです。

---

## なぜ「生き残ったコード」なのか

活動は、盛れます。コミットは分割できるし、lockfile で数千行は出る。詰めれば PR 数は増える。忙しさは、いくらでも演出できる。

生き残りはそうはいきません。コードが著者より長く残ったかどうかは、時間が経たないと分からない。一晩では盛れない。タイポ修正もアーキテクチャ変更も「1 PR」だけど、半年後に立っているコードは嘘をつけません。

[EIS](https://github.com/machuz/eis) は、その層を読む OSS の CLI です。`git log` と `git blame` だけで7軸と3つのトポロジーを観測して、JSON に吐く。外部APIもAIトークンも要りません。`brew install` して `eis` を叩くだけ。式は全部[ホワイトペーパー](https://github.com/machuz/eis/blob/main/docs/whitepaper.md)に出してあるので、中身は丸見えです。

---

## AIが、活動量を完全に無意味にした

これが効いてくるのが、今です。

コードを書く速度が、人の手を離れました。AIに頼めば1000行が数分で出てくる。コミット数も変更行数も、もう「その人が動いた量」じゃなくて「ツールが動いた量」を映している。活動量という指標は前から怪しかった。AIがそれを、完全に無意味にしました。

じゃあ何が残るか。生き残ったコードです。AIが吐いた1000行のうち、来週には書き直される分の survival はゼロ。半年経っても立っているコードだけが、構造として効いている。生成が無限に安くなった世界で、希少なのは出力の量じゃなくて、残る方です。

しかも生き残りは、AIをもってしても盛れません。時間だけで決まっていないからです。

あるコードが残るかどうかは、それが置かれた生態系で決まります。次の人が土台にして書き進めるのか、邪魔だと思って書き直すのか。周りの開発者の手が、答えを出す。だから絶対的な物差しではありません。現場ごとに変わる。保守的な環境なら、多少いまいちでもバグを産まないコードをそのまま残すかもしれないし、攻めるチームなら同じものを来月には捨てているかもしれない。生き残りは、その現場の中でだけ効く相対的な指標です。

ただ、だからこそ盛れない。自己申告でも書いた量でもなく、周りが使い続けたかどうかという、他人の選択の積み重ねだからです。そして、いくつもの違う現場で残るコードを書ける人は、きっと本当に設計を考えられる人。ひとつの環境の癖にたまたま合っただけ、では説明がつかなくなる。

もうひとつ。観測は、生成のちょうど逆です。世の中がAI生成であふれるほど、地面に刻まれた事実をそのまま読む道具の価値は上がる。EIS はモデルを使いません。推論もしないし、ハルシネーションも起きない。git にもう書いてあることを、読むだけ。生成の時代に観測へ徹する、というのが立ち位置です。

## ただし、読み方を間違えると壊れる

ここが本題です。

生き残りシグナルを上から読んで、名前の横に数字を置いた瞬間、それは得点表になります。そして得点表は、測ったものを必ず歪める。人は数字を最適化しはじめ、現場の手触りは数字の下に潰れる。エンジニアリング指標が「順位づけと詰め」に化けて死ぬのは、いつもこの瞬間です。

だから問いは「git から構造を読めるか」じゃない。「読めるとして、評価に堕とさずに読めるか」です。観測する装置だけでは足りない。どう読むかが、それが助けになるか害になるかを分けます。

これが、EIS と Ace を分けている理由です。

- **EIS（望遠鏡）は観測する。** git を読んでシグナルを返すだけ。推薦も予測も評価もしない。事実に徹する。
- **Ace（天文台）は観測を読む。** ただし順位ではなく、年表に読む。

観測する道具が意味まで決めはじめると、どこからが事実でどこからが意見か分からなくなる。望遠鏡を事実に徹させて、解釈は天文台に引き受けさせる。両方を信じられるのは、そこに境界を引いているからです。

## 天文台が読むもの

機能の一覧ではなく、git が隠していた構造の話として読んでください。

**Structural Summary。数字を、文章に。** 「Survival 23」だけ言われても困りますよね。設計が弱いのか、レガシーを書き換え中なのか分からない。Ace はシグナル全体を読んで、いま何が立って何が崩れかけているかを文章で説明します。

**コンウェイの法則チェック。組織図 vs 実態。** 人のトポロジーとモジュールのトポロジーを並べて、ズレを見せます。「このサービスはAチーム担当」のはずが、実は書いていない。知識がいつのまにか別の人に移っていた。そういうやつです。

**崩壊リスク。事故になる前に。** 誰も触らないから残っているだけのモジュール。オーナーが辞めて宙に浮いたモジュール。バスファクター1。リスクは最初から git 履歴の中にあった。Ace は、それが事故になる前に表に出します。

**組織年表（Chronicle）。この製品の心臓です。** 得点表ではありません。エンジニアを順位づけない。代わりに、このコードベースが何をくぐってきたかを記録する。乗り越えたマイグレーション、ある subsystem を作って去ったアーキテクト、オーナーが変わって脆くなったモジュール。

得点表は、人がゲームの仕方を覚える。年表は、チームが愛着を持つ。狙っているのは後者です。シグナルは見たければ覗けますが、主役じゃなくて、近くで見るときのレンズ扱いにしてあります。

## 入口は二つ、宇宙はひとつ

**望遠鏡（OSS）は、完全に無料で使えます。** ローカルで完結する設計で、アカウントもログインも連携もいらない。`brew install` して、リポに向けるだけ。

```bash
brew install machuz/tap/eis
cd your-repo
eis analyze .
```

**天文台（SaaS）は、数クリックで始まります。** [ace.orbitlens.io](https://ace.orbitlens.io) を開いて、GitHub でログインして、観たいリポジトリを選ぶ。あとは Ace が観測を回し続けて、構造的サマリーもコンウェイ検証も崩壊リスクも年表も、ブラウザの中で読めるように可視化します。CLI を覚える必要はありません。

自分の組織に、個人のリポジトリに、気になっている OSS に、レンズを当ててみてください。公開リポは無制限なので、有名な OSS の重力地図を覗くだけでも、何か見えてきます。

EIS（望遠鏡）はずっと無料・OSS です。席制限もトライアル期限も、肝心なところだけ有料のオープンコアもなし。アイデアに課金したいわけじゃなくて、広がってほしいだけ。壁の向こうに置いたら広がらないので。

お金がかかるのは Ace の方。観測を回し続けて読み返すのは、ちゃんとインフラなので。それでも壁ではなく、手の届く値段にしてあります。**Free** $0（〜5人、公開リポ無制限、履歴6ヶ月）、**Pro** $7/月（個人、全期間、フルの Gravity Certificate）、**Nova** $39/月（8席込）+ $18/席（組織レベルの読みが要る非公開チーム向け）。この手の分析 SaaS が「開発者ひとり月$15〜50、しかも contact sales の向こう」が相場なのに対して、Ace は8席までフラットで、その下のエンジンは無料です。持ち運べる Gravity Certificate は、どのプランでも作成も検証もずっと無料。自分の仕事を証明するのに、お金は取りません。

## 最後に、正直なところ

エンジニアリングを上から測った瞬間、現場の肌感覚は平らに潰れがちです。数字が来ると、その人が実際にやったことの手触りが、その下に隠れてしまう。

その逆を作りたい。でも、できているとは言い切れません。シグナルはシグナルで、判定じゃない。git に映らないものは測らないし、測れないとはっきり言います。メンタリング。コミットにならなかった設計の議論。障害のとき、誰かが保っていた落ち着き。これが望遠鏡の届かないダークマターです。低いシグナルは「貢献が小さい」じゃなくて、たいてい組織側のシグナルだったりします。

人を測るのは、善意でも危うい。現場の感覚を一度も貶さずに測る方法を、まだ見つけられたとは思っていません。だからこれは、本気のお願いです。自分のを、チームのを見て、「なんか違う」「平らにされた」「大事だったやつが抜けてる」と思ったら、教えてください。そのズレている所が、次に直す場所だから。

OrbitLens のビジョン — 観測から継承へ

The OrbitLens Vision — From Observation to Succession.

観測は、機能ではなく能力だ

ダッシュボードは機能だ。アラートもグラフもスコアも機能だ。機能はコピーされる。誰かが出せば、翌四半期には三社が同じものを並べる。そうなれば、あとは価格と営業の勝負だ。

観測は別の層にある。git に残った事実を、推論もモデルも通さずに読む。何が生き残り、どのコードが誰か一人に寄りかかっているかを返す。これは機能ではなく能力だ。能力はコピーできない。今まで誰も言葉にできなかった問いに、名前がつく。名前のついた問いは、やがてカテゴリになる。OrbitLens が作っているのは、それだ。

見えれば、決められる

観測そのものは目的じゃない。価値があるのは、観測が変える判断のほうだ。何が見えると、何を決められるようになるのか。

  • 採用。 コミット数ではなく、いくつもの現場で生き残ったコードを書いた人が分かる。肩書きの下にある、構造を実際に支えた事実で人を見る。
  • 離職の予防。 この人が抜けたら、このサブシステムを誰も分からなくなる。その崩壊は、起きる前から git 履歴に書いてある。バスファクター1が見えていれば、先に手を打てる。
  • 知識の継承。 去った人が何を分かっていたか。それをコードの構造として、読める形で残す。次の人が受け継ぐのは、謎ではなく構造だ。
  • 開発速度。 組織図と、実際に誰が何を書いているかのズレが見える（コンウェイ検証）。知識がどこへ動いたかが分かる。配置を実態に寄せれば、摩擦は減る。

見えれば、決められる。観測は判断の材料をそろえる。判断そのものは、人が下す。

本質は、継承だ

人は辞める。組織は組み変わる。ツールは1000行あたりの値段を変える。それでも最後に残さなきゃいけないのは、ここにいた人が分かっていたことだ。守るのは人じゃない。人は去るし、去っていい。守るのは知識だ。観測は、その知識を、書いた人が去ったあとも読める状態に保つ。継承のためにある。

だから OrbitLens は観測で終わらない。観測を継承につなぎ、継承を次の設計につなぐ。三つのサービスが、その円を回している。

ACE · 観測 git に残った構造を読む。何が生き残り、誰に寄りかかっているか。組織が今どこにいるかを、事実で押さえる。
TRUE · 継承 観測を、人が持ち運べる記録（Gravity Certificate）にする。組織を越えて、知識と信頼が引き継がれる。
IDEAL · 設計 観測をためた組織の写しから、次を予報する。この配置のまま進むと、半年後どこが詰まるか。その上に、選べる航路を何本か引く。どれを通るかは人が決める。
→ 実行 · 新しい履歴 設計は実行され、新しいコミットになる。履歴が積もり、円はまた ACE の観測へ戻る。

観測する。継承する。設計する。実行する。また観測する。この円が閉じているあいだ、組織は学び続ける。一度やって終わりじゃない。数週間後にもう一度観測して、効果を測って、次の設計に回す。円が閉じていることが、組織が賢くなり続ける条件だ。

組織のデジタルツインを作る

ACE の観測は予測じゃない。git に残った事実を読むだけで、推論はしない。だからハルシネーションもない。観測であって、生成ではない。ただ、観測をためていくと、組織の写しができる。誰がどのコードを支え、どこが一人に寄りかかっているか。これが組織のデジタルツインだ。OrbitLens はこれを作る。

写しがあれば、次が読める。この配置のまま進むと、半年後どのサブシステムを誰も引き継げなくなるか。どこで速度が落ちるか。IDEAL はそれを天気予報のように出す。傘を持つかどうかを自分で決めるように、どの航路を通るかも人が決める。IDEAL は予報の上に航路を何本か引く。選ぶのは人だ。

観測と継承という文化

順位表は、その人が抜けた瞬間に忘れられる。年表は、次のオーナーが最初に開くものになる。OrbitLens が残したいのは得点表じゃない。組織が自分の来歴を読んで、次の人へ手渡していく習慣だ。

機能はコピーされる。能力はカテゴリを作る。そのカテゴリの名前が、観測と継承の文化だ。

OrbitLens のビジョン — 観測から継承へ

The OrbitLens Vision — From Observation to Succession.

観測は、機能ではなく能力だ

ダッシュボードは機能だ。アラートも、グラフも、スコアも機能だ。機能はコピーされる。誰かが作れば、翌四半期には三社が同じものを出す。機能の競争は、最後には価格と営業の競争になる。

観測は、そことは別の層にある。git に刻まれた事実を、推論もモデルも介さずに読み、何が生き残り、誰の手に構造が寄りかかっているかを返す——これは一個の機能ではなく、一つの能力だ。能力はコピーされない。能力は、それまで言葉にできなかった問いに名前を与える。そして名前のついた問いは、カテゴリになる。機能は市場の中で競い、能力は市場そのものの形を変える。OrbitLens が作っているのは、後者だ。

観測で何が見えるか → どんな意思決定ができるか

観測そのものは目的ではない。観測の価値は、それが変える意思決定の側にある。何が見えると、何が決められるようになるのか。

  • 採用。 活動量ではなく、いくつもの現場で生き残ったコードを書いた人が見える。肩書きではなく、構造を支えた事実で人を読む。
  • 離職の予防。 「この人が抜けたら、このサブシステムは誰も分からない」——その崩壊リスクは、事故になる前から git 履歴に書いてある。バスファクター1が見えれば、手当てができる。
  • 知識の継承。 去った人が何を分かっていたかを、コードの構造として読める状態に保つ。次の人が、謎ではなく構造を受け継ぐ。
  • 開発速度。 組織図と実態のズレ（コンウェイ検証）が見えれば、知識がどこへ移ったか、どのチームが実際に書いているかが分かる。配置を実態に合わせれば、摩擦が減る。

見えることは、決められることに変わる。観測は、より良い意思決定の前提であって、意思決定そのものを肩代わりはしない。判断は人が下す。

本質は、継承だ

人は辞める。組織は組み変わる。ツールは1000行の値段を変える。それでも最後まで残らなければならないのは、ここにいた人が分かっていたことだ。守るのは人ではない——人は去っていくし、去っていい。守るのは知識だ。観測は、その知識を去ったあとも読める状態に保つためにある。観測は、継承のためにある。

だから OrbitLens は、観測で終わらない。観測を継承につなぎ、継承を次の設計につなぐ。三つのサービスは、その一つの円を回している。

ACE · 観測 git に刻まれた構造を観測する。何が生き残り、誰に寄りかかっているか。組織が今いる場所を、事実として読む。
TRUE · 継承 観測を市場へ開示し、人とともに持ち運べる記録（Gravity Certificate）にする。組織を越えて、知識と信頼を継承する。
IDEAL · 設計 観測された現在地から、安定した次の軌道を設計する。成長経路と最適な配置を。未来を当てるのではなく、選べる航路を描く。
→ 実行 · 新しい履歴 設計は実行され、新しいコミットになる。新しい履歴が刻まれ、円はふたたび ACE の観測へ戻る。

観測する → 継承する → 設計する → 実行する → また観測する。この円が閉じているあいだ、組織は学び続ける。一度の介入で終わらず、N週後に再び観測して効果を測り、次の設計につなぐ。学習がループとして閉じていることが、組織が賢くなり続ける条件だ。

これは、予測ではない

はっきりさせておきたい。これは未来を予測する装置ではない。組織の「デジタルツイン」を作って、起きることを当てにいくものでもない。EIS の核心は一貫している——観測であって、生成ではない。git にもう書いてあることを読むだけで、推論しないので、ハルシネーションも起きない。

IDEAL が描くのは予言ではなく、設計だ。地図が天気を予報しないのと同じで、現在地を正確に観測したうえで、選べる航路を引く。どの航路を取るかは、人が決める。予測は判断を奪うが、観測は判断の前提を整えるだけだ。OrbitLens は前者を作らない。

観測と継承という文化

順位づける指標は、対象が抜けた瞬間に忘れられる。記録する年表は、次のオーナーが最初に読むものになる。OrbitLens が残したいのは、得点表ではなく、組織が自分の来歴を読み、次の人へ手渡していく習慣だ。

機能はコピーされる。能力はカテゴリを作る。そのカテゴリの名前は、観測と継承という文化だ。
